# Reflection · dry run vs. the AWSpec's assumptions, and vs. the earlier Lovable test

**The conflict-check branch had never actually been run before.** Every document (AWSpec, Control Panel, PRD) describes what happens when Jira and Slack disagree, this dry run is the first time an example actually produced that state. It confirmed the rule works as written: high confidence (82%) did not override the conflict flag, PM review still triggered. That's the behaviour the spec claims, good to see it hold on a real case rather than just read as a sentence.

**This test and the earlier Lovable RAG test aren't actually testing the same thing**, worth being clear-eyed about that rather than treating them as two data points on the same question. The Module 3 test (`03-rag-prd/juno-rag-diff.md`) re-ranked an already-known list of three priorities and found RAG changed the wording, not the ranking. This dry run does something structurally different: it takes one new escalation and scores it from scratch into a single graded card with a confidence number and a citation. There's no ranking to compare here, no "did the order change." The honest comparison is narrower than "does RAG help", it's "does a single escalation get scored the way the spec says it should", and on that narrower question, yes.

**The metric-gaming guardrail (One-Pager Risk 2) actually had to do something on this run.** Customer Retention was retrieved as a candidate pillar and genuinely tempting to cite, it's not wrong that a QBR-blocking issue touches retention. But the pillar's own definition is calibrated to SMB churn specifically, and this is an enterprise, deadline-driven issue, a different shape of risk. Citing it anyway would have been exactly the "two tangentially related sources" failure mode the One-Pager warns about. Worth noting this wasn't a hypothetical risk, it was a real fork in this run.

**What this doesn't prove:** this isn't evidence the system behaves this way at scale, under load, or under an actual LLM's non-determinism, it's evidence the logic in the spec is internally consistent and produces the intended routing on one worked example. That's the ceiling of what a dry run without a real runtime can show. The Langflow path is still the way to test actual model variance, latency, and tool-call failure modes for real.
