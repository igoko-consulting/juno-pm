PM Execution Plan

How I'd ship Juno

Where the work is today, what ships next, what I watch, and what would block a launch.

01 · Now

Where Juno is today

- All six modules drafted (M1 to M6) and cross-referenced.
- A walkthrough by hand of one reconstructed escalation shows the spec routes a Jira/Slack conflict to PM review even at high confidence.
- Not yet running against a live model or in production, and the golden set is not built.
- Modelled payback of about four quarters on PM time saved (Strategy One-Pager §2). It excludes running costs, PM review and grading time, and the upside of fewer wrong bets.
02 · Next

What ships next

- Sprint 1: build the 100-item golden set and wire the code-based CI checks (format, citation, evidence-balance). This closes the biggest open gap: accuracy has been shown on one worked case, not at scale.
- Sprint 2: rebuild Juno Agent.json in Langflow and run it against a live model to measure model variance, latency and tool-call failures, which the golden set can't test.
03 · Watch

What I watch

- Daily: Manual Override rate, time-to-approve / un-actioned rate, cost per run against the 50-run daily cap (modelled at $6 or more a day).
- Weekly: decision-reversal rate, human-rubric mean per dimension, evidence-balance gate trigger rate.
- Per release (CI gate + nightly cron): golden-set accuracy, format/citation/evidence-balance pass rate.
04 · Red lines

What blocks shipping

- <90% golden-set accuracy on the automated layer (eval-stack.md pass bar).
- 0% fabricated PII, ARR, or customer names.
- 0 critical safety fails (any score of 1) on the human-eval Safety/refusal dimension.
- Any citation-check failure.
- Anything published without a PM approval click.
05 · Governance

How I keep it safe

- Compliance: no external comms, no publishing without human review (system prompt Refusal Conditions; PRD requirement 6).
- Safety: hard refusal on PII, ARR, contracts, and legal/regulator requests, routed to the human PM (system prompt guardrails).
- Reliability: evidence-balance gate blocks any card where one source type supplies more than 80% of citations; p95 latency target under 3s (PRD requirement 1).
- Reputation: trust-gap mitigations address hallucination, opacity, and control directly (04-ai-ux/trust-gaps.md), not just citations and an approval button.
Build insights

What I learned

The honest three: where it hurt, what clicked, and the moment something changed.

😵 Friction

The one before-and-after RAG test reworded the priorities but did not change the ranking. Whether grounding changes what gets prioritised is still to be shown on the golden set.

🧠 Learning

A repo-wide audit caught what no single-module review would, M1's system prompt described a different output shape than everything built after it. Each module was fine alone, the set wasn't consistent with itself.

💡 Aha

Reading the AWSpec isn't the same as running it. The Jira/Slack conflict-check branch was described in three documents but never exercised until the dry run proved the conflict flag correctly overrode a high confidence score.
